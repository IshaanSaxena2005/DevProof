# Product screenshots — capture checklist

The README's Product Preview section will embed these images once they exist.
Capture them against the running stack (`docker compose up -d --build`, or
Option B from the README) with a Chromium window at **1440 × 900**, and save
them under `screenshots/` using exactly these filenames:

- [ ] `screenshots/01-landing-page.png` — public landing page
- [ ] `screenshots/02-login-register.png` — login and registration forms
- [ ] `screenshots/03-demo-overview.png` — public demo, overview section (sample-data badge visible)
- [ ] `screenshots/04-dashboard-overview.png` — signed-in dashboard overview
- [ ] `screenshots/05-repositories.png` — connected repositories list
- [ ] `screenshots/06-repository-analysis.png` — repository detail with metrics and findings
- [ ] `screenshots/07-developer-360.png` — Developer 360 aggregation
- [ ] `screenshots/08-skills-intelligence.png` — skills with evidence ladder
- [ ] `screenshots/09-problem-solving.png` — coding-platform activity heatmap
- [ ] `screenshots/10-learning-achievements.png` — certifications, courses, hackathons, resume
- [ ] `screenshots/11-growth-analytics.png` — growth history charts
- [ ] `screenshots/12-career-readiness.png` — readiness score and requirement evidence
- [ ] `screenshots/13-ai-insights.png` — AI insights (or its honest empty state)
- [ ] `screenshots/14-settings.png` — account and connected-platform settings
- [ ] `screenshots/15-mobile-responsive.png` — dashboard at 390 px, no horizontal overflow

When a file exists, its image is added to the README's Product Preview
section with a one-line caption — the README deliberately links nothing
that is not on disk yet.
